## 三、factCount=21 是怎么来的

`FactExtractor.extractRecord()`（L82-96）从每条部门记录抽取**标量字段**为 Fact 三元组 `(entity, metric, value, source)`：
- 跳过实体名键 `ENTITY_KEYS`（`deptName`/`deptId` 等；`deptName` 用作 entity，L26-27、L102-110）；
- 跳过复合结构：`value instanceof Map || value instanceof List`（L86）——`performanceDistribution`、`employmentTypeDistribution` 是 Map，**不入 FactSet**。

每部门保留 **7 个标量指标**：`headcount`、`currentStaff`、`headcountUsageRate`、`turnoverRate`、`probationPassRate`、`averageTenureYears`、`totalEmployees`。

**7 × 3 部门 = 21 条 Fact**，与日志 `factCount=21` 精确吻合。

其中驱动本次回答的 3 条 `turnoverRate` 事实：

| entity | metric | value | source |
|---|---|---|---|
| 技术部 | turnoverRate | 0.08 | TOOL |
| 人力资源部 | turnoverRate | 0.05 | TOOL |
| 财务部 | turnoverRate | 0.03 | TOOL |

## 六、数据权限（R2）在本次链路中的体现

`manager_001` 经 `MockUserDirectory.resolve()` 得到 `managedOrgIds = [DEPT_TECH, DEPT_HR, DEPT_FIN]`，功能权限含 `team:view`。

关键点：
1. **权限前置**：`TeamMetricsTool.execute()` L49-68 在**查询层**按 `scope` 过滤部门（`deptId=null` 时只返回 scope 内部门，越权/空 scope 直接 fail），而非查完再过滤（R2）。
2. **跨线程透传**：`ToolExecutor` 用 `CompletableFuture.supplyAsync`（ForkJoinPool 线程）执行工具，`UserContextHolder`（ThreadLocal）默认不跨线程传递；`executeWithTimeout` 中显式捕获 `callerContext` 并在任务体内 set / finally 恢复，否则工具内 `scope=null` 会误拒。
3. **对照实验**（前次实跑验证）：
   - `manager_001` → `离职率：技术部 8%、人力资源部 5%、财务部 3%`（全部）
   - `manager_tech`（仅辖 DEPT_TECH）→ `离职率：技术部 8%`（只见管辖部门）
   - `ghost_user`（无权限）→ 无 team:view，被 ToolDispatcher 拒，返回兜底话术，**无数据泄露**

## 八、校验局限与残留风险（复审新增，勿过度声称）

以下均为 `verifyByFacts` 的真实局限。**模板渲染路径不受影响**（渲染器只输出正确指标的正确归属，天然满足校验），风险仅在 **LLM 回退合成路径**（`composeAnswer` 未命中模板时）暴露。详见 `20261022_003_链路V2复审.md` 第四节。

| 编号 | 局限 | 影响面 | 说明 |
|---|---|---|---|
| A | `containsEntityValue` 跨指标盲区 | 中（仅 LLM 路径） | "任一指标命中即可"（`FactSet` L76/L83-93）：能拦跨实体张冠李戴，拦不住"离职率：技术部 92%"（0.92 是技术部转正率）。证据 `FactExtractorTest` L34。 |
| B | 句子切分粒度粗 | 低 | `splitSentences` 不含 `、`/`：`，多部门答案为一整句，全对才 true → 得分二值化（1.0/0.0），无部分粒度。当前偏保守（安全侧）。 |
| C | 值在实体前时退化 | 中（仅 LLM 路径） | `nearestPrecedingEntity` 只找数值**之前**的实体；LLM 若输出"8% 是技术部离职率" → owner=null → 退化为 `factSetContainsValue`（只校验值存在、不校验归属）。 |
| D | 模板路径校验自证 | 信息项 | 答案由 FactSet 渲染、又用同一 FactSet 校验 → 恒过。零幻觉的真正保证来自**渲染器的确定性**，critic 的价值集中在 LLM 回退路径。 |

**结论性认知**：扩大模板覆盖率（让更多纯数据查询走 `DataTemplateRenderer`）比调 critic 阈值更能提升安全性。风险 A/C 的补强（指标语境绑定 + 双向实体就近搜索）是否落地，取决于 LLM 回退路径的实际占比，当前优先级中低。
