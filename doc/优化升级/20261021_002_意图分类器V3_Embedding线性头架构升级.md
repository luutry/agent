## 一、问题背景

### 1.1 V2 根本缺陷

V2 `KeywordIntentClassifier` 将意图分类简化为**关键词计数投票**：

```
意图 = argmax(TOOL关键词命中数, RAG关键词命中数, CHITCHAT关键词命中数)
```

这一假设存在两个不可修复的理论缺陷：

**缺陷一：共享关键词污染**

"绩效怎么算"（问制度→RAG）和"看看张三绩效"（要数据→TOOL）共享"绩效"关键词。
分类结果取决于哪边关键词列表更长，而非查询的真实语义。

**缺陷二：句式轴与依赖源轴正交**

| | 问方法（怎么/如何） | 问事实（看看/查下） |
|---|---|---|
| **需要数据库** | "怎么查看员工绩效" → TOOL | "看看张三绩效" → TOOL |
| **需要知识库** | "绩效怎么算" → RAG | "绩效制度是什么" → RAG |

句式决定"问什么类型的问题"，不决定"答案在哪里"。V2 把句式当作意图信号，必然误分类。

### 1.2 升级目标

从"人工编规则猜意图"转变为"模型从语义空间学意图"。

## 二、方案选型

### 2.1 候选方案对比

| 方案 | 描述 | 语义理解 | 可训练性 | 冷启动 | 改动量 |
|------|------|---------|---------|--------|--------|
| A: 改进关键词规则 | 增加更多关键词、更复杂的权重规则 | 无 | 无 | 无需 | 小 |
| B: LLM 直接分类 | 每次查询调用 LLM 判断意图 | 强 | 无需 | 依赖API | 中 |
| **C: Embedding + 线性头** | **查询→向量→Wx+b→softmax** | **强** | **可训练** | **种子数据** | **中** |
| D: 小模型微调 | BERT/DistilBERT 微调分类 | 强 | 可训练 | 需标注数据 | 大 |

### 2.2 方案A排除

改进关键词规则本质上还是在给错误的地基打补丁，无法解决"共享关键词"和"句式正交"两个理论缺陷。

### 2.3 方案B排除

LLM 直接分类每次查询增加一次 LLM API 调用（~500ms + token 成本），对 QPS > 100 的入口不可接受。

### 2.4 方案D排除

需要标注数据集 + GPU 训练 + 模型部署，当前阶段投入产出比不合理。

### 2.5 方案C选定

**Embedding + 线性头** 的核心优势：
1. **语义理解**：Embedding 编码完整语义，"绩效怎么算"和"张三绩效"在向量空间天然不同
2. **可训练**：权重矩阵可通过标注数据离线训练，配置热更新
3. **冷启动**：无训练权重时用种子数据余弦相似度分类，无需标注也能工作
4. **性能**：Embedding 调用 ~100ms，线性头计算 < 1ms，远低于 LLM 方案
5. **降级完备**：三级降级保证任何情况下不阻断主流程

## 三、架构设计

### 3.1 整体架构

```
用户查询 "查看员工绩效并对比制度"
       │
       ▼
┌─────────────────────────────────┐
│   EmbeddingIntentClassifier     │
│   (implements IntentClassifier) │
│                                 │
│  ① embed(query) → float[1024]  │
│       │                         │
│  ② 分类路径选择                  │
│     ├─ 有权重 → 线性头 Wx+b     │
│     ├─ 有种子 → 余弦相似度      │
│     └─ 都没有 → 降级关键词      │
│       │                         │
│  ③ softmax → [T,R,M,C] 概率    │
│       │                         │
│  ④ MIXED判定 + 置信度阈值检查   │
│       │                         │
│  ⑤ IntentResult(intent, conf)   │
└─────────────────────────────────┘
       │ 异常时降级
       ▼
┌─────────────────────────────────┐
│  KeywordIntentClassifier        │
│  (纯降级 Bean，非 @Component)   │
│  关键词匹配 + 绝对评分          │
└─────────────────────────────────┘
```

### 3.2 三级降级策略

```
Level 1: 权重矩阵可用（训练完成后）
  → classifyByLinearHead(embedding, query)
  → logits = W·x + b → softmax → 概率分布
  → 最高效、最准确

Level 2: 仅种子数据可用（冷启动阶段）
  → classifyBySeedSimilarity(embedding, query)
  → 余弦相似度 → softmax → 概率分布
  → 无需训练，但精度依赖种子质量

Level 3: Embedding 调用失败（网络/服务异常）
  → fallbackClassifier.classify(query)
  → 关键词匹配 + 递减收益评分
  → Agent 铁律 #1: catch Throwable，绝不阻断
```

### 3.3 数学模型

**线性分类头**：

```
logits[c] = Σ W[c][i] × embedding[i] + bias[c]   (c ∈ {TOOL, RAG, MIXED, CHITCHAT})
probs[c] = softmax(logits)[c]
```

**Softmax 数值稳定性**：

```
maxLogit = max(logits)
probs[c] = exp(logits[c] - maxLogit) / Σ exp(logits[i] - maxLogit)
```

**余弦相似度**（种子路径）：

```
classSim[c] = avg(cosine(queryEmb, seedEmb) for seed in seeds[c])
probs = softmax(classSim)
```

**MIXED 判定**：

```
if probs[TOOL] >= mixedThreshold AND probs[RAG] >= mixedThreshold:
    return MIXED
```

```java
// LlmConfig.java

@Bean
public EmbeddingModel embeddingModel() {
    return OpenAiEmbeddingModel.builder()
            .baseUrl(baseUrl)
            .apiKey(apiKey)
            .modelName(embeddingModelName)  // "text-embedding-v3"
            .timeout(Duration.ofSeconds(timeoutSeconds))
            .build();
}

@Bean
public EmbeddingService embeddingService(EmbeddingModel embeddingModel) {
    return new DashScopeEmbeddingService(embeddingModel);
}

@Bean
public KeywordIntentClassifier keywordIntentClassifier(IntentClassificationPolicy policy) {
    return new KeywordIntentClassifier(
            policy.getFallbackToolKeywords(),
            policy.getFallbackRagKeywords(),
            policy.getFallbackChitchatKeywords()
    );
}

@Bean
@Primary
public IntentClassifier intentClassifier(EmbeddingService embeddingService,
                                         IntentClassificationPolicy policy,
                                         KeywordIntentClassifier keywordIntentClassifier) {
    return new EmbeddingIntentClassifier(embeddingService, policy, keywordIntentClassifier);
}
```

### 4.4 核心分类流程

```java
@Override
public IntentResult classify(String query) {
    if (query == null || query.isBlank()) {
        return IntentResult.chitchat();
    }
    try {
        float[] queryEmbedding = embedWithTimeout(query);
        if (queryEmbedding == null) {
            return fallbackClassifier.classify(query);  // 降级
        }
        ensureSeedsEmbedded();  // 懒初始化种子向量
        if (hasWeights()) {
            return classifyByLinearHead(queryEmbedding, query);
        } else if (hasSeeds()) {
            return classifyBySeedSimilarity(queryEmbedding, query);
        } else {
            return fallbackClassifier.classify(query);  // 降级
        }
    } catch (Throwable t) {  // Agent 铁律 #1
        return fallbackClassifier.classify(query);  // 降级
    }
}
```

## 五、配置说明

### 5.1 application.yml 配置段

```yaml
agent:
  intent-classification:
    embedding-model: "text-embedding-v3"
    embedding-dim: 1024
    confidence-threshold: 0.5       # 最高概率低于此值 → CHITCHAT(不确定)
    mixed-threshold: 0.3            # TOOL 和 RAG 概率均 ≥ 此值 → MIXED
    embedding-timeout-ms: 2000      # Embedding 调用超时
    weights: []                     # 空 = 冷启动用种子余弦相似度
    bias: [0.0, 0.0, 0.0, 0.0]    # [TOOL, RAG, MIXED, CHITCHAT]
    tool-seeds:
      - query: "查看研发部门员工绩效"
      - query: "团队有多少人"
      # ... 更多种子
    rag-seeds:
      - query: "绩效制度是什么"
      - query: "离职流程怎么规定"
      # ... 更多种子
    mixed-seeds:
      - query: "查看员工绩效并对比制度标准"
    chitchat-seeds:
      - query: "你好"
      - query: "谢谢"
```

### 5.2 权重热更新

训练完成后，将权重矩阵填入 `weights` 配置项即可切换到线性头路径，无需重启：

```yaml
agent:
  intent-classification:
    weights:
      - [0.012, -0.003, ...]  # TOOL 行 (1024维)
      - [-0.008, 0.015, ...]  # RAG 行
      - [0.005, 0.002, ...]   # MIXED 行
      - [-0.010, -0.005, ...] # CHITCHAT 行
```

### 6.3 Softmax 概率分布注意事项

4 类 softmax 中，即使 logits = [1, 0, 0, 0]，最大概率也仅 ≈ 0.475（非直觉上的 0.731）：

```
softmax([1,0,0,0]) = [e^1, e^0, e^0, e^0] / (e^1 + 3·e^0)
                    = [2.718, 1, 1, 1] / 5.718
                    = [0.475, 0.175, 0.175, 0.175]
```

因此测试中 `confidenceThreshold` 设为 0.4（而非 0.5），种子路径断言使用 `> 0.4`。

## 七、方案局限性与后续规划

### 7.1 当前局限

1. **Embedding 依赖外部 API**：DashScope API 不可用时降级到关键词（精度下降但可用）
2. **冷启动精度**：种子余弦相似度路径精度低于训练后的线性头
3. **超时控制简化**：当前 `embedWithTimeout` 为直接调用，生产环境需加虚拟线程超时
4. **种子数据人工维护**：种子质量直接影响冷启动分类效果

### 7.2 后续规划

| 优先级 | 事项 | 说明 |
|--------|------|------|
| P1 | 权重训练 Pipeline | 收集线上分类日志，离线训练权重矩阵 |
| P1 | Embedding 超时控制 | 虚拟线程 + Future.get(timeout) |
| P2 | 温度参数 | softmax 引入温度系数，调节分布尖锐度 |
| P2 | 可观测埋点 | 记录分类路径、耗时、置信度分布 |
| P3 | 在线学习 | 增量更新权重，适应语义漂移 |
| P3 | 种子数据扩充 | 覆盖更多业务场景 |
