## 二、改动明细与原因

### 1. 脱敏 fail-closed（R3）

**原因**：`QueryInputDesensitizer` 与 `DefaultQueryCleaner` 的异常路径都返回原文。
脱敏是入站唯一闸门，异常时"放行原文"等于把 R3 交给运气；R3 是铁律，不能为可用性让路。

**改动**：

- `QueryInputDesensitizer.desensitize` 的 `catch (Throwable)` 改为调用 `failClosedMask`：
  把所有半角/全角数字替换为 `*`，纯字符遍历、不依赖正则，保证不会二次抛异常；
- `DefaultQueryCleaner.clean` 的兜底改为 `CleanResult.degraded(failClosedMask(input), ...)`，
  降级文本不再包含数字；
- 覆盖范围说明：R3 列举的可数字表征 PII（手机/身份证/银行卡/工号）全部被抹掉；
  邮箱等文本类 PII 不在 R3 列举内，极端降级下仍可能残留，属于已知残余风险。

### 2. 不可见字符与全角归一化（R3）

**原因**：`CONTROL_CHAR_PATTERN` 只覆盖到部分 Cf 字符，且**刻意保留 ZWJ/ZWNJ**。
保留的结果是 `138\u200C12345678` 不在 `1[3-9]\d{9}` 内 → 不脱敏；`绩\u00AD效` 命中不了关键词。
另一条更常见的绕过是输入法产出的全角数字 `１３８…`。

**改动**：

- 控制字符集合扩到 Cf 全量：软连字符 `\u00AD`、`\u061C`、`\u180E`、`\u200B-\u200F`（含 ZWJ/ZWNJ）、
  `\u2060-\u2064`、`\uFFF9-\uFFFB`；原"保留 ZWJ/ZWNJ"的测试改为断言移除；
- 新增 `normalizeFullWidthAlnum`：只把全角字母/数字转半角（`U+FF10-FF19/FF21-FF3A/FF41-FF5A`），
  不动全角标点，避免破坏下游标点合并与规则拆分。

**取舍**：ZWJ 移除会让 emoji 连字（👨‍👩‍👧）在清洗后拆成单个 emoji。查询文本不承担展示职责，
脱敏可靠性优先；该取舍在代码注释与本文中留痕。

### 3. 带分隔符的号码（R3）

**原因**：常见写法 `138 1234 5678`、`138-1234-5678`、`+86 138…` 全部躲过连续正则。

**改动**：`QueryInputDesensitizer` 增加预扫描 `SEPARATED_DIGITS`：

1. 先按"可选 `+86` + 数字与分隔符交替"匹配候选串；
2. 用 `NON_DIGIT` 抽出纯数字；
3. 只对**数字个数**恰好为 11（`1[3-9]` 开头）、13（`86` 前缀）、18、16-19 的串脱敏；
4. 其余（日期 `2026-10-22`、普通编号）原样保留。

脱敏格式仍复用 `PiiMaskerFactory` 的 masker，避免两套脱敏规则漂移。

### 4. 词边界截断方向（质量）

**原因**：`findWordBoundary` 的循环把 `lastWordBoundary` 覆盖到窗口**最左**边界，
与 Javadoc"选择最接近 from 的词边界"相反。用 jshell 实测（`from=1500, window=50`）：
`preceding(1501)=1498`，旧实现返回 `1450` —— 每次 WORD 截断白丢约 48 字符，
被丢掉的恰好是最靠近问题的部分。

**改动**：直接返回 `preceding(...)` 的结果，且必须落在 `[searchStart, from]` 内，否则交回 `CODE_POINT`。

### 5. `hardLimited` 标记（可观测）

**原因**：硬截断（`warn × multiplier`）发生后，最终 1500/2000 截断会重写 `boundary`，
埋点上看不出"输入曾被硬上限削过"；`degraded` 又固定写 `HARD_LIMIT`，语义自相矛盾。

**改动**：`CleanResult` 新增 `hardLimited` 字段，由 `clean()` 计算并透传；
`degraded` 增加三参重载，降级路径按最坏情况标记。`QueryRouter` 日志带上该标记。

### 6. 埋点脱敏（R4）

**原因**：`@AgentTrace(stage = "query_clean")` 挂在 `clean(rawQuery)` 上，
`AgentTraceAspect.buildInputSummary` 把**清洗前的原文**写进 `AgentLog`（截断 500 字符）。
为脱敏而调用的方法，自己先泄漏了一份。

**改动**：Aspect 对入参摘要、出参摘要统一调用 `PiiMaskerFactory.maskText`，
先脱敏再截断（先截断会把手机号截成半截导致正则失效）；脱敏抛异常时写 `[REDACTED]`。
收益覆盖所有 `@AgentTrace` 方法，包括工具出参与 RAG 结果。

### 7. Controller：日志、拒答、截断声明（R4/R7）

**原因**：

- 原文日志发生在清洗**之前**，清洗再彻底也管不到它；
- `hardRejected` 全仓库只有 getter 和一行日志，超长输入被截成 2000 字后照常回答，
  用户不知道答案只基于前一段内容，违反 R7"超限必须中止并说明原因"。

**改动**：

- 请求日志改为 `queryLength=...`，不再打印任何内容；
- 预处理后检查 `isHardRejected()`：直接 `ApiResponse.fail(PARAM_ERROR, "查询超过长度上限…")`，
  不进入 Planner，省掉无效工具轮次；
- `isTruncated()`：在 `ChatResponse.issues` 追加"查询过长已被截断…"，
  与 `critique` 的问题列表合并（不改写 answer，避免干扰 `SelfCritique` 的事实校验）。

### 8. history 同管道（R3）

**原因**：`request.getHistory()` 原样交给消解器；省略式追问时，消解器会把 history 里的实体/整句
拼回 `resolvedQuery`，PII 就此绕过清洗进入 Prompt。

**改动**：`QueryRouter` 用同一个 `QueryCleaner` 逐个清洗 history turn（空串剔除），
再交给 `CoreferenceResolver`。清洗器已包含脱敏、截断与噪声清理，历史不会被二次放大。

### 9. 阈值收敛与启动校验（R7）

**原因**：`CleanPolicy` 自持 1500/2000/4，`AgentConstants.MAX_QUERY_LENGTH` 与
`HARD_LIMIT_MULTIPLIER` 无人引用；且 `warn=0` 或负数会让硬截断直接变 0，
所有查询清成空串、全线 CHITCHAT，一个 yml 手滑就静默瘫痪。

**改动**：

- 默认值改为引用 `AgentConstants`（`warn = hard = MAX_QUERY_LENGTH = 2000`，`multiplier = 4`）；
- `@PostConstruct validate()` 修正非法值：非正数回退默认、`hard < warn` 抬到 `warn`、
  语义窗口超出阈值回退 50；只告警不抛异常（R8）。

## 三、行为变化

| 场景 | 改前 | 改后 |
|---|---|---|
| `联系 138 1234 5678` | 原样进 Prompt | `联系 138****5678` |
| `联系 +86 138 1234 5678` | 原样 | `联系 138****5678` |
| `１３８１２３４５６７８` | 原样（全角绕过） | `138****5678` |
| `138\u200C12345678` | 原样（ZWNJ 绕过） | ZWNJ 移除后正常脱敏 |
| `绩\u00AD效` | 关键词匹配失败 | 归一化为 `绩效` |
| history 含手机号 + 省略式追问 | PII 随消解回流 | history 先脱敏 |
| 埋点 `query_clean` 入参 | 原文 500 字符 | 脱敏后文本 |
| 2500 字查询 | 截到 2000 照常回答 | 400 + "超过长度上限" |
| 1500~2000 字查询（yml 配 1500 时） | 静默截断 | 正常回答 + `issues` 声明 |
| 词边界截断 | 多丢 ≈48 字符 | 贴近阈值截断 |
| `clean-policy: warn=0` | 全部查询变空 | 启动告警并回退 2000 |

> 默认阈值从 1500 提到 2000（对齐 `MAX_QUERY_LENGTH`）。若 `application.yml` 显式配置了
> `clean-policy`，仍以 yml 为准，`validate()` 只修非法值。

## 六、风险与回滚

| 风险 | 影响 | 回滚方式 |
|---|---|---|
| 超长查询改为拒答 | 前端需处理 400 与提示文案 | 调大 `clean-policy.hard-reject-threshold-chars`，或恢复"截断后回答 + issues 声明" |
| ZWJ 移除 | emoji 连字被拆开 | 仅影响 query 文本，展示层不受影响；如需保留可把 `\u200C-\u200D` 从集合中摘出，但会重新打开 ZWNJ 绕过 |
| 脱敏 fail-closed 抹数字 | 极端异常下查询失真、可能落到 CHITCHAT | 仅在 `maskText` 抛异常时触发；如需更保守可改为返回固定占位串并直接拒答 |
| 词边界修复后截断更长 | 单条 query 多约 50 字符进入下游 | 上下文预算由 `MAX_TOKEN_BUDGET` 控制，影响可忽略 |
| 阈值默认值变更 | 2000~旧上限之间的查询由"截断"变"正常处理" | yml 显式配置即可覆盖 |
