## 1. 现象

查询「本月各部门离职率是多少」（userId=manager_001），team_metrics 成功返回数据，但 verdict=REJECT，有效回答被替换为拒绝话术。

## 2. 复现步骤

1. 启动 Agent 服务
2. POST `/api/agent/chat`，body：`{"query":"本月各部门离职率是多少","userId":"manager_001","sessionId":"s1"}`

**期望**：verdict=PASS，返回各部门离职率
**实际**：verdict=REJECT

## 3. 根因分析

四个叠加缺陷（均经读码 + 实跑验证，非推断）：

**RC1 数据流两份真相（直接致 REJECT）**：同名的两个 `formatToolResult` 行为不一致——
`ReActEngine` 版把 `metrics` 列表逐条展开（LLM 看到真实数值），而 `DefaultContextAggregator` 版把 List 压成 `[3 items]`：

```java
// 修复前 DefaultContextAggregator.formatToolResult
if (value instanceof List) {
    sb.append("[").append(((List<?>) value).size()).append(" items]"); // 部门名与数值全部丢失
}
```

校验方 `detectHallucination` 拿到的 contextText 里没有任何部门名和数值，无论何种匹配策略都命中不了 → hallucinationScore=0 → REJECT。001 记录里"上下文是 turnoverRate=0.05 文本"是臆测，与实际不符。

**RC2 纯数据走 LLM 合成**：TOOL 指标查询本可确定性渲染，却交给 LLM 改写，制造幻觉面。

**RC3 上一次的"关键词重叠"是危险退行**：`hasKeywordOverlap` 只要句中出现任一上下文词就放行，使「数字对、归属错」的张冠李戴（如"技术部离职率3%"，3% 实属财务部）完全免疫，违反 R5。

**RC4 R2 数据权限缺位**：`UserContextHolder.set()` 主链路从不执行；`ToolDispatcher.checkPermissions` 因 `get()==null` 连功能权限都跳过；`TeamMetricsTool` 在 deptId=null 时返回全部部门；且工具在 `CompletableFuture.supplyAsync`（ForkJoinPool）执行，ThreadLocal 根本不跨线程。

## 4. 修复方案

以「Fact 三元组唯一真相源」重构，四项联动：

- **②单一真相源**：删除 `PipelineEnvelope`/`EnvelopeStageRecord`，`ReActEngine.execute` 返回 `ExecutionResult`（原始 ToolResult/RetrievalResult/MemoryEntry），`AgentResponse` 携带 `ExecutionResult`+`FactSet`；`AgentController` 聚合与校验都从这一份取数。
- **③模板渲染**：新增 `DataTemplateRenderer`，TOOL 纯数据用 `FactSet` 确定性渲染（如"离职率：技术部 8%…"），不经 LLM。
- **①精确校验**：`FactExtractor` 从 ToolResult 提取 `FactSet`；`DefaultSelfCritiqueService` 删除 `hasKeywordOverlap`，有事实时按 `verifyByFacts` 校验——句中每个数值必须确属于其就近前置实体，捕获张冠李戴。
- **④数据权限前置**：`AgentController` 入口 `UserDirectory.resolve→UserContextHolder.set`、finally clear；`ToolExecutor` 跨异步线程传递 UserContext；`TeamMetricsTool` 在查询层按 `managedOrgIds` 过滤，空范围/越权一律拒绝、不静默截断。
- 附带修复 `DefaultContextAggregator.formatToolResult` 递归展开 List/Map，消除 RC1。

```java
// verifyByFacts 核心：值必须确属于就近前置实体，否则判幻觉
String owner = nearestPrecedingEntity(entityNames, entityPositions, valuePositions.get(i));
if (owner != null) {
    if (!factSet.containsEntityValue(owner, value)) return false; // 张冠李戴
} else if (!factSetContainsValue(factSet, value)) {
    return false;
}
```

放弃的方案：继续用「上下文文本 + 模糊匹配」兜底——治标不治本，且模糊放行本身就是 R5 破口。
