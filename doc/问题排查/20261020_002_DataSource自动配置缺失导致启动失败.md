# 【Bug记录】DataSource自动配置缺失导致应用启动失败
> 编号：002
> 发生时间：2026-10-20 22:00
> 模块归属：基础设施配置层
> 严重等级：P0
> 影响范围：应用完全无法启动，阻断所有Agent对话主流程

## 1. 现象 & 复现步骤
【现象】
Spring Boot 启动时报 `BeanCreationException`，提示 DataSource 配置失败：`'url' attribute is not specified and no embedded datasource could be configured`。

【复现步骤】
1. IDE 中运行 `com.luutry.agent.Main` 启动类（已修复 001 号 Bug 后）
2. 预期结果：应用正常启动，Tomcat 监听 8080 端口
3. 实际结果：启动失败，HikariDataSource 实例化异常

## 2. 日志/报错信息
```
2026-10-20T22:01:01.101+08:00  WARN  ConfigServletWebServerApplicationContext :
Exception encountered during context initialization - cancelling refresh attempt:
org.springframework.beans.factory.BeanCreationException: Error creating bean with name
'dataSource' defined in class path resource
[org/springframework/boot/autoconfigure/jdbc/DataSourceConfiguration$Hikari.class]:
Failed to instantiate [com.zaxxer.hikari.HikariDataSource]: Factory method 'dataSource'
threw exception with message: Failed to determine a suitable driver class

***************************
APPLICATION FAILED TO START
***************************

Description:
Failed to configure a DataSource: 'url' attribute is not specified
and no embedded datasource could be configured.

Reason: Failed to determine a suitable driver class
```

同时存在 MyBatis mapper 扫描警告：
```
WARN  o.m.s.mapper.ClassPathMapperScanner : No MyBatis mapper was found
in '[com.luutry.agent]' package. Please check your configuration.
```

## 3. 根因分析（Root Cause）
**配置缺失 — application.yml 缺少 DataSource 配置项**

- `pom.xml` 引入了 `mybatis-plus-spring-boot3-starter`、`mysql-connector-j`、`spring-boot-starter-data-redis` 等依赖
- Spring Boot 自动配置检测到 classpath 中存在 DataSource 相关类，触发 `DataSourceAutoConfiguration`
- 但 `application.yml` 仅配置了 `server.port` 和 `spring.application.name`，缺少 `spring.datasource.url` 等数据库连接信息
- 当前项目所有存储层均使用内存实现（`InMemoryShortTermStore`、`InMemoryLongTermStore`），RAG 检索使用内存 BM25 + Dense Retriever，**不需要真实数据库连接**
- 因此正确的做法是排除 DataSource 自动配置，而非补充数据库连接参数

## 4. 修复方案
- 改造思路：排除当前不需要的 DataSource 自动配置，同时完善 `application.yml` 补充 MyBatis-Plus 和日志配置
- 修改文件清单：
  - `src/main/java/com/luutry/agent/Main.java`
  - `src/main/resources/application.yml`
- 关键改动说明：
  - `Main.java`：`@SpringBootApplication` 添加 `exclude = {DataSourceAutoConfiguration.class, DataSourceTransactionManagerAutoConfiguration.class}`
  - `application.yml`：新增 MyBatis-Plus mapper 扫描路径配置（消除 mapper 扫描警告）、日志级别配置、预留 MySQL/Redis 连接配置注释模板
- 是否兼容原有逻辑：**是**，仅排除不需要的自动配置 + 补充配置项，无业务逻辑变更

## 5. 风险评估
- 引入新Bug风险：**低** — 排除的自动配置在当前阶段无代码使用，不影响任何业务功能
- 回滚方案：移除 `Main.java` 中 `@SpringBootApplication` 的 `exclude` 参数，并在 `application.yml` 补充真实数据库连接信息
- 是否需要数据补偿：**否**

## 6. 测试验证用例
【正向验证】
- 启动应用成功，无 BeanCreationException
- `POST /api/agent/health` 返回 `{"code":"000000","data":"Agent is running"}`
- Tomcat 正常监听 8080 端口

【边界验证】
- 确认排除 DataSource 后，所有内存实现的 Service Bean 正常注册和注入
- 确认 MyBatis mapper 扫描警告消除

【回归用例】
- 全量单元测试 435 个用例全部通过（BUILD SUCCESS）
- 应用启动时间 7.6 秒，无异常日志

## 7. 后续优化项（可选）
- 生产部署时需：移除 `Main.java` 中的 `exclude` 配置，在 `application.yml` 中配置真实 MySQL/Redis 连接信息
- 考虑按环境区分配置：`application-dev.yml`（排除 DataSource）vs `application-prod.yml`（配置真实连接）
- 引入 `@Profile` 注解区分开发环境和生产环境的 Bean 注册策略
- 补充 `@SpringBootTest` 启动链路集成测试，CI 阶段提前暴露配置问题
