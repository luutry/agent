# 离线训练权重矩阵方案 — 从数据收集到上线部署

> 本文档说明如何为 `EmbeddingIntentClassifier` 的线性分类头（Wx+b → softmax）离线训练权重矩阵，
> 替代当前的种子余弦相似度冷启动方案，提升分类准确率。

---

## 一、当前方案 vs 训练方案对比

| 维度 | 当前：种子余弦相似度 | 目标：离线训练权重矩阵 |
|------|----------------------|------------------------|
| 原理 | 查询向量与种子向量算余弦距离 | 查询向量乘以权重矩阵得到各类别得分 |
| 数据量 | 6+6+2+3=17 个种子（人工编写） | 需要 200~1000 条标注数据 |
| 分类能力 | 只能区分"离哪个种子近" | 能学到复杂的语义决策边界 |
| 启动依赖 | 依赖 Embedding API 在线计算种子向量 | 不依赖，权重直接写在配置里 |
| 启动速度 | 首次请求需 17 次 API 调用 | 零延迟，权重已预计算 |
| 迭代方式 | 手动调种子文本 | 重新训练 → 替换配置文件 → 重启 |

**核心区别**：种子方案是"人工挑几个代表点，看新查询离谁近"；训练方案是"用大量标注数据，自动学出一条最优分界线"。

---

## 二、训练什么？—— 数学本质

### 2.1 我们的模型

```
查询文本 → Embedding模型 → float[1024] → W·x + b → softmax → [TOOL, RAG, MIXED, CHITCHAT] 概率
```

需要训练的参数：
- **W（权重矩阵）**：维度 `[4][1024]`，4 行分别对应 4 个类别
- **b（偏置向量）**：维度 `[4]`

总共 `4 × 1024 + 4 = 4100` 个浮点数。

### 2.2 本质就是 Softmax 回归（多项逻辑回归）

这是机器学习中最基础的分类模型，等价于神经网络没有隐藏层的情况：

```
输入层(1024维) ──全连接──→ 输出层(4维) ──softmax──→ 概率分布
                权重W,b                          最大概率 = 预测类别
```

### 2.3 为什么用这么简单的模型？

1. **Embedding 已经做了重活**：text-embedding-v3 已经把语义编码到 1024 维向量里了，线性头只需要在已经分好的语义空间里画几条分界线
2. **可解释性强**：每个权重有明确含义，不像深度学习是黑箱
3. **训练快、推理快**：几百条数据训练几秒完成，推理就是一次矩阵乘法（微秒级）
4. **不容易过拟合**：参数少 + 数据量适中 = 泛化好

## 三、数据收集

### 3.1 数据格式

每条训练数据是一个 `(查询文本, 意图类别)` 对：

```json
{"query": "查看研发部门员工绩效", "label": "TOOL"}
{"query": "绩效制度是什么", "label": "RAG"}
{"query": "查看员工绩效并对比制度标准", "label": "MIXED"}
{"query": "你好", "label": "CHITCHAT"}
```

### 3.2 四个类别的标注指南

| 类别 | 定义 | 典型句式 | 标注示例 |
|------|------|----------|----------|
| **TOOL** | 答案来自业务数据库（需要查人/查数据） | "查看/盘点/统计/列表/几个人/哪些人" | "研发部有多少人"、"张三的档案"、"离职名单" |
| **RAG** | 答案来自 HR 规章制度文档 | "制度/规定/流程/怎么算/什么条件/政策" | "请假流程怎么走"、"晋升条件是什么"、"考勤规定" |
| **MIXED** | 同时需要查数据 + 查制度 | "查看X并对比制度"、"X的数据和相关规定" | "团队离职率和离职制度"、"绩效分布和评分规则" |
| **CHITCHAT** | 不需要任何外部数据 | 问候/感谢/闲聊/无意义 | "你好"、"谢谢"、"今天天气不错" |

### 3.3 关键：收集容易混淆的数据

最有价值的数据不是"明显属于某类"的样本，而是**容易分错的边界样本**：

```
✅ 高价值（边界样本）：
"绩效怎么算"         → RAG（问制度规则，不是要查某人的绩效数据）
"看看张三绩效"       → TOOL（要查具体人的数据，不是问制度）
"绩效"              → CHITCHAT（太模糊，不知道要干嘛）
"帮我看看绩效制度"   → RAG（虽然有"看看"像 TOOL，但核心是"制度"）

❌ 低价值（太简单）：
"查看员工列表"       → TOOL（太明显，没有训练价值）
"你好啊"            → CHITCHAT（太明显）
```

### 3.4 数据量建议

| 阶段 | 每类样本数 | 总样本数 | 预期准确率 |
|------|-----------|----------|-----------|
| 最小可用 | 30~50 | 120~200 | 75~85% |
| 推荐 | 100~150 | 400~600 | 85~92% |
| 充分 | 200~300 | 800~1200 | 92~96% |

**类别不平衡要注意**：四个类别的样本数尽量接近（差异不超过 2 倍）。如果 CHITCHAT 只有 20 条但 TOOL 有 200 条，模型会偏向 TOOL。

### 3.5 数据来源

1. **人工构造**：根据标注指南，由了解业务的人编写（冷启动最快）
2. **线上日志收集**：系统上线后，记录用户真实查询 + 人工标注分类结果
3. **LLM 辅助生成**：用大模型批量生成变体（需人工审核质量）

```
示例：用 LLM 生成变体
Prompt: "请生成10个HR场景下管理者可能问的关于'查人'的问题，要求表述方式多样"
→ "帮我看看研发团队都有谁"
→ "研发部现在几个人"
→ "给我拉一下研发部门的人员清单"
→ ...
```

### 4.3 步骤 2：向量化

调用 DashScope Embedding API 把每条 query 转为 float[1024]：

```python
# scripts/train/embed_data.py（伪代码）
import json, requests

def embed(text: str) -> list[float]:
    """调用 DashScope Embedding API"""
    resp = requests.post(
        "https://dashscope.aliyuncs.com/compatible-mode/v1/embeddings",
        headers={"Authorization": "Bearer sk-xxx"},
        json={"model": "text-embedding-v3", "input": text}
    )
    return resp.json()["data"][0]["embedding"]

# 读取训练数据，逐条向量化
samples = []
with open("data/train.jsonl") as f:
    for line in f:
        item = json.loads(line)
        vec = embed(item["query"])
        samples.append({"query": item["query"], "label": item["label"], "embedding": vec})

# 保存为带向量的完整训练集
with open("data/train_embedded.json", "w") as f:
    json.dump(samples, f)
```

### 4.4 步骤 3：训练（Softmax 回归）

```python
# scripts/train/train.py（伪代码）
import numpy as np

# ---- 加载数据 ----
# X: shape [N, 1024]，每行是一个查询的 embedding
# y: shape [N]，每个值是 0/1/2/3（对应 TOOL/RAG/MIXED/CHITCHAT）

# ---- 标签编码 ----
label_map = {"TOOL": 0, "RAG": 1, "MIXED": 2, "CHITCHAT": 3}

# ---- 训练参数 ----
n_classes = 4
n_features = 1024
learning_rate = 0.01
n_epochs = 200
reg_lambda = 0.001  # L2 正则化，防止过拟合

# ---- 初始化权重 ----
W = np.zeros((n_classes, n_features))  # [4][1024]
b = np.zeros(n_classes)                 # [4]

# ---- 训练循环（梯度下降）----
for epoch in range(n_epochs):
    # 前向传播：scores = X @ W.T + b → softmax → probs
    scores = X @ W.T + b
    probs = softmax(scores)  # [N, 4]

    # 计算损失（交叉熵 + L2 正则）
    loss = -np.mean(np.log(probs[range(N), y] + 1e-8)) + reg_lambda * np.sum(W**2)

    # 反向传播：计算梯度
    grad = probs  # [N, 4]
    grad[range(N), y] -= 1  # one-hot 相减
    grad /= N

    dW = grad.T @ X + 2 * reg_lambda * W  # [4, 1024]
    db = np.sum(grad, axis=0)              # [4]

    # 更新参数
    W -= learning_rate * dW
    b -= learning_rate * db

    if epoch % 50 == 0:
        print(f"Epoch {epoch}: loss={loss:.4f}")

# ---- 导出 ----
# W → 写入 application.yml 的 weights 字段
# b → 写入 application.yml 的 bias 字段
```

## 五、部署到项目

### 5.1 导出格式

训练完成后，将 W 和 b 导出为 YAML 格式：

```python
# scripts/train/export_yaml.py
import yaml, json

# W: shape [4, 1024] → List[List[float]]
# b: shape [4] → List[float]
config = {
    "weights": W.tolist(),   # [[0.001, -0.003, ...], [...], [...], [...]]
    "bias": b.tolist()        # [0.1, -0.05, 0.02, -0.07]
}

with open("trained_weights.yml", "w") as f:
    yaml.dump(config, f)
```

### 5.2 写入 application.yml

```yaml
agent:
  intent-classification:
    embedding-model: "text-embedding-v3"
    embedding-dim: 1024
    confidence-threshold: 0.5
    mixed-threshold: 0.3
    embedding-timeout-ms: 2000

    # ===== 训练好的权重（替换空数组）=====
    weights:
      - [0.0012, -0.0034, 0.0056, ...]   # TOOL 行（1024 个浮点数）
      - [-0.0023, 0.0041, -0.0011, ...]   # RAG 行
      - [0.0005, 0.0003, 0.0008, ...]     # MIXED 行
      - [-0.0010, -0.0020, -0.0015, ...]  # CHITCHAT 行
    bias: [0.1, -0.05, 0.02, -0.07]

    # 种子数据保留（作为权重不可用时的降级后备）
    tool-seeds: [...]
    rag-seeds: [...]
```

### 5.3 代码自动选择路径

当前 `EmbeddingIntentClassifier` 已经内置了路径选择逻辑：

```java
if (hasWeights()) {
    // 路径 A：权重矩阵可用 → 线性头分类（最快、最准）
    return classifyByLinearHead(queryEmbedding, query);
} else if (hasSeeds()) {
    // 路径 B：无权重但种子可用 → 余弦相似度（冷启动）
    return classifyBySeedSimilarity(queryEmbedding, query);
} else {
    // 路径 C：都没有 → 关键词兜底
    return fallbackClassifier.classify(query);
}
```

`hasWeights()` 判断条件：`weights` 列表有 4 行，且每行非空。
- 填入训练好的权重 → 自动走路径 A
- `weights: []`（空数组）→ 自动走路径 B

**无需改任何代码**，只需替换配置文件。

### 5.4 部署检查清单

- [ ] 权重维度校验：`weights` 必须是 4 行，每行 1024 个浮点数
- [ ] 偏置维度校验：`bias` 必须是 4 个浮点数
- [ ] 顺序一致性：行顺序必须是 `[TOOL, RAG, MIXED, CHITCHAT]`
- [ ] 交叉验证准确率 ≥ 85%
- [ ] 混淆矩阵中没有某类 recall < 70%
- [ ] 种子数据保留不删除（降级后备）

### 6.1 迭代流程

```

   ↑                                                              |
   └──────────────────────────────────────────────────────────────┘
```

### 6.2 日志收集（已内置）

`EmbeddingIntentClassifier` 每次分类都会输出 debug 日志：

```
意图分类[LINEAR_HEAD]: query=帮我看看绩效制度, confidence=0.87 → RAG
```

可观测层记录完整链路，可批量导出用户查询 + 分类结果。

### 6.3 主动学习策略

优先标注以下类型的样本（对模型提升最大）：

1. **低置信度样本**：`confidence < 0.6` 的查询 → 模型不确定，补充类似样本帮助它划清边界
2. **降级触发的样本**：走了关键词兜底的查询 → 说明 Embedding 或权重有问题
3. **用户纠正的样本**：用户说"不是这个意思" → 最有价值的负反馈

## 七、常见问题

### Q1：一定要用 Python 训练吗？

不一定。可以用任何工具，只要能输出 `[4][1024]` 的权重矩阵和 `[4]` 的偏置向量。
甚至可以用 PyTorch/TensorFlow，但对于线性模型来说杀鸡用牛刀了。

### Q2：训练需要 GPU 吗？

不需要。1024 维输入 × 4 类输出 × 几百条数据，CPU 几秒钟就训练完了。

### Q3：Embedding 模型换了，权重需要重新训练吗？

**需要**。不同 Embedding 模型产生的向量空间不同，权重矩阵是绑定特定 Embedding 模型的。
当前绑定的是 `text-embedding-v3`，如果换模型，必须用新模型重新向量化训练数据并重新训练。

### Q4：权重文件很大（4×1024=4096 个浮点数），配置文件中好管理吗？

约 40KB 的 YAML。可以接受。如果后续觉得配置文件太大，可以改为从数据库/文件加载：
```yaml
agent:
  intent-classification:
    weights-file: "classpath:intent-weights.json"
```

### Q5：能不能在线学习（自动更新权重）？

理论上可以，但当前阶段不建议。原因：
1. 在线学习需要自动标注（谁来告诉模型正确答案？）
2. 错误标注会污染权重，导致分类质量退化
3. 离线训练 + 人工审核 + 配置发布 的流程更安全可控
