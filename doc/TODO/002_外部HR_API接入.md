# 002 外部 HR API 接入

| 字段 | 内容 |
|---|---|
| 状态 | 待开始 |
| 优先级 | P0 |
| 关联阶段 | Phase 4 之前 |
| 影响模块 | `external`、`tool` |
| 前置依赖 | 接口文档、鉴权凭证、联调环境、限流配额确认 |

## 背景

部分人事数据（如组织架构、汇报关系、实时在职状态）由上游 HR 系统提供，
本地 MySQL 只能覆盖历史快照。当前 `HrApiClient` 为 `MockHrApiClient`，返回固定样例。

## 为什么暂缓

接口未开放，鉴权方式与限流策略未确认。

## 目标

新增真实 HTTP 客户端，具备完整的超时、重试、熔断、降级能力，
**失败不得影响主流程**（AGENTS.md R8）。

## 实施要点

1. **只读**：只允许调用查询类接口，禁止调用任何写接口（R1）。
2. 超时：连接 1s / 读取 2s；仅幂等 GET 允许重试 1 次。
3. 熔断：错误率 > 50%（窗口 20 次）熔断 30s，熔断期间直接返回降级结果。
4. 降级：返回空结果 + `degraded=true` 标记，聚合层据此在答案中说明「数据暂不可用」。
5. 鉴权凭证从环境变量读取，禁止写进 yml（R10）。
6. 响应字段映射到内部模型，**不要直接把上游 DTO 泄漏到业务层**。
7. 所有出参在进入 Prompt 前必须经过 `PiiMasker`（R3）。

## 验收标准

- [ ] 上下游接口联调通过（至少 2 个查询接口）
- [ ] 超时、重试、熔断、降级各有独立单测（用 WireMock 或本地 stub）
- [ ] 熔断触发后主流程仍能返回可读答案
- [ ] 凭证不出现在日志与异常栈中
- [ ] 上游 5xx 时不重试非幂等请求

## 风险

- **接口变更**：上游字段改名或结构变化，需要版本适配层
- **限流**：批量查询可能触发配额，需要本地缓存与合并请求
- **数据一致性**：上游与本地 MySQL 可能不一致，需明确「以谁为准」
- **响应体过大**：需要分页与字段裁剪
