# 009 多意图检测与任务分解

> 状态：**已完成（规则版，2026-10-22）** | 优先级：**P1** | 关联阶段：预处理管道重构 Phase 2

## 背景

管道编排已修正为 `clean → resolve → decompose → per-unit classify → aggregate`（见 QueryRouter.route），
但步骤 3「复合判定」当前为保守实现——始终产出单单元，不做实际拆分。

这意味着以下场景仍无法正确处理：

| 用户输入 | 期望行为 | 当前行为 |
|---|---|---|
| 我年假剩几天，另外社保基数多少 | 拆成 2 个 unit，分别路由 TOOL/RAG | 单 unit，整句 embedding 平均，路由大概率错 |
| 团队有多少人？离职率是多少？ | 拆成 2 个 unit，均路由 TOOL | 单 unit，关键词分类器可能命中但无法区分子意图 |
| 查一下张三的绩效和考勤 | 单 unit（共享谓语的并列宾语），不应拆 | 单 unit（正确，但靠运气不靠逻辑） |

## 前置依赖

1. **RuleBasedTaskDecomposer 的触发条件需要重写**
   - 当前连词表 `还有/同时/以及/逗号` 存在严重多义词误判（详见问题排查记录）
   - 需要引入「共享谓语检测」，区分并列宾语 vs 并列意图
   - 需要引入多意图分类器（可能是 LLM few-shot 或规则 + 置信度联合判定）

2. **slots（typed 实体抽取）需要先落地**（见 TODO 010）
   - 拆分后的 unit 需要携带结构化实体，否则子路由无法独立执行

3. **aggregateIntents 聚合逻辑已就绪**
   - QueryRouter 中的聚合方法已实现：全同 → 单路由，不同 → MIXED
   - 多单元产出后直接接入即可

## 方案草案

### 触发条件收窄

```
复合判定 = true 当且仅当：
  (a) 存在多个独立谓语核心（非共享谓语的并列宾语）
  OR
  (b) 多个问号且各自指向不同信息源
  OR
  (c) 显式多意图标记词（另外/还有[表并列时]/此外）+ 后续片段含独立谓语
```

### 实现路径

- 短期：规则 + 谓语提取（动词核心计数），覆盖 80% 场景
- 中期：LLM few-shot 判定（输入 query → 输出 unit 列表），加超时降级到规则
- 接口：替换 QueryRouter 中的保守实现为 `TaskDecomposer.decomposeToUnits(resolved)`

## 验收标准

1. 以下 case 正确拆分（isComposite=true，units.size()>1）：
   - `我年假剩几天，另外社保基数多少` → 2 units
   - `团队有多少人？离职率是多少？` → 2 units
2. 以下 case 不拆分（isComposite=false，units.size()=1）：
   - `我年假还有几天` → 1 unit（"还有"表剩余）
   - `年假以及病假的区别` → 1 unit（共享谓语）
   - `你好，我想问下年假` → 1 unit（寒暄 + 单意图）
3. 拆分后各 unit 独立分类，aggregate 结果正确
4. 全量测试通过，无回归
