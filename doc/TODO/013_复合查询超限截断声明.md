# 013 复合查询超限截断声明

| 字段 | 内容 |
|---|---|
| 状态 | 待开始 |
| 优先级 | P2 |
| 关联阶段 | 预处理拆分（TODO-009 规则版）之后 |
| 影响模块 | `preprocessor.router`、`planner`、`critique` |
| 前置依赖 | 无（但需要产品确认声明文案） |

## 背景

复合查询拆分后，子任务数受 `AgentConstants.MAX_SUB_TASK_COUNT`（5）限制。
当前超出时只保留前 5 个并打 WARN 日志（`RuleBasedTaskDecomposer.decompose`），
**没有在答案里告诉用户"还有几问没有处理"**。

用户看到的是一个完整回答，会误以为所有子问题都已覆盖——这与 R5「数据不足就说不足」同类：
不编造数字，但隐式声明了"全部已答"这个错误前提。

## 目标

当拆分结果被截断时，在最终答案末尾追加显式声明，例如：
「（本次包含 6 个问题，仅处理了前 5 个，请拆分后继续提问）」。

声明不得包含业务数字，避免干扰 `DefaultSelfCritiqueService` 的数值校验。

## 验收标准

- [ ] 6 个独立子问题的查询被截断为 5 个，答案包含截断声明
- [ ] 声明不含业务数值，`FactSet` 数值校验不受影响（单测断言）
- [ ] 未截断时不出现该声明
- [ ] 声明文案不泄露原始 query（R4）

## 风险

- 声明文案需要产品确认，直接写死可能与前端交互冲突。
- 若后续改为并行执行或动态上限，该声明逻辑需要同步调整。
