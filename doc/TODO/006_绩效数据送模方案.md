# 006 绩效数据送模方案（当前决策：保持禁止）

| 字段 | 内容 |
|---|---|
| 状态 | 已决策-保持禁止 |
| 优先级 | — |
| 关联阶段 | 全阶段适用 |
| 影响模块 | `security`、`tool`、`critique` |
| 前置依赖 | 法务 / 合规评审、数据分级制度 |

## 背景

绩效记录（评分、等级、评语、申诉记录）属于人事数据中敏感度最高的一类。
本项目明确：**绩效记录不得以任何形式进入 LLM**，包括原文、摘要、片段。

## 当前规则

- `PerformanceQueryTool` 只返回聚合值：分布、均值、等级比例。
- `PiiMasker` 对绩效字段做**丢弃**而非掩码（掩码仍可能泄漏位数）。
- `ContextAggregator` 在合并前校验：来源为绩效且粒度为「员工级」的结果直接剔除。
- `SelfCritique` 若发现答案中出现员工级绩效明细，直接拒答并记录告警。

## 为什么不做（而不是暂缓）

1. 绩效评语含主观评价，一旦进入第三方模型，无法撤回。
2. 摘要仍然可能保留可识别信息（如「某员工连续两次 C」）。
3. 当前无合规依据支持把绩效原文送出域外。

## 若未来要开放，前置条件

- [ ] 法务与合规出具书面意见
- [ ] 模型部署在企业内网（不出域）
- [ ] 可逆脱敏方案评审通过（且证明无法还原）
- [ ] 全链路审计日志（谁、何时、查了谁的绩效）
- [ ] 员工知情与授权机制
- [ ] 灰度 + 可一键关闭

## 替代方案（当前采用）

| 需求 | 当前做法 |
|---|---|
| 「我们团队绩效怎么样」 | 返回等级分布、均值、同比 |
| 「谁绩效最好」 | 返回 TopN 的**姓名 + 等级**，不含分数与评语 |
| 「张三绩效如何」 | 返回「等级 B，最近三个周期稳定」，不含评语原文 |

## 验收标准

- [ ] 全仓库搜索：无任何路径把 `PerformanceRecord` 整体放入 Prompt
- [ ] 单测：构造带绩效明细的上下文，断言其被聚合层剔除
- [ ] 单测：答案生成后校验无员工级绩效字段

## 风险

- 业务方可能反复要求「就这一次」——规则必须硬编码在代码里，不能靠配置开关
- 聚合值在小团队（< 5 人）时仍可能反推个人，需要最小样本量限制（如 < 5 人不出分布）
