## 背景

- R3.1 禁止绩效明细进入 LLM。2026-10-22 已在 `ToolResultSanitizer` 中剔除员工级绩效字段
  （score/grade/comment/appealed/performanceGrade/latestPerformance），并移除
  `EmployeeProfileTool` 的 `latestPerformance` 产物。
- `performance_record` 工具现在能被正确调用（`ToolParameterExtractor` 补 `employeeId`），
  但 `DataTemplateRenderer` 没有绩效指标，答案回退 LLM 后只能得到「信息不足」，工具价值未兑现。
- 正确做法应是按 TODO-006「替代方案」在服务端确定性生成答案，不经 LLM。

## 待确认（未确认前不得实现，AGENTS §5）

1. 展示哪些周期：最近 1 个 / 最近 3 个 / 全部？
2. 是否展示分数，还是仅等级（TODO-006 只提到等级）？
3. 「稳定」的判定口径（连续同等级？波动阈值？）。
4. 小团队聚合的最小样本量（TODO-006 提到 < 5 人不出分布）。

## 目标

「张三绩效如何」返回服务端渲染的等级结论（及约定周期范围），不调用 LLM，
答案中不含评语原文，渲染与校验继续走 `usedFactKeys ⊆ FactSet.keys()`。

## 验收标准

- [ ] 绩效查询答案不经 LLM（单测断言 `LlmService.generateAnswer` 未被调用）
- [ ] 答案无评语原文、无员工级明细越界（R3.1）
- [ ] 渲染绑定的 `usedFactKeys` 全部属于 `FactSet.keys()`
- [ ] 用例覆盖：单周期 / 多周期 / 无记录 / 越权部门
- [ ] 周期口径写入答案，不静默省略用户的时间限定（R5）

## 风险

- 口径未定前实现等于猜业务规则，会重演「模板化后更难补口径」的问题。
- 绩效等级在小团队仍可能反推个人，需要最小样本量限制配合。
