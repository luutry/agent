# 005 组织树与数据权限真实数据

| 字段 | 内容 |
|---|---|
| 状态 | 待开始 |
| 优先级 | P0 |
| 关联阶段 | Phase 2 之后 |
| 影响模块 | `security`、`repository` |
| 前置依赖 | 组织架构数据源确认（本地表 / 上游接口）、汇报关系字段确认 |

## 背景

`DataScopeResolver` 已在 Phase 2 定义，当前依赖 `MockOrgDataProvider`，
用固定 JSON 模拟组织树与汇报关系。权限逻辑本身可测，但**数据是假的**。

## 为什么暂缓

组织树与汇报关系的真实来源未确认；兼岗、代理、虚拟团队等边界规则未定义。

## 目标

用真实数据替换 `MockOrgDataProvider`，`DataScopeResolver` 逻辑不变。

## 待确认的业务规则

1. **组织树向下展开**：是否包含所有层级？还是只到某一级？
2. **汇报关系**：直属下属 + 隔级下属？矩阵汇报（双线）怎么算？
3. **兼岗**：一个人属于多个部门时，权限取并集还是主部门？
4. **代理**：管理者休假期间代理人的权限如何继承？
5. **虚拟团队**：跨部门项目组的成员数据，管理者能否看？
6. **离职员工**：历史数据是否仍可见？可见多久？

以上每一条都必须由业务方确认，**禁止自行假设**（AGENTS.md 第 5 节）。

## 实施要点

- 组织树递归必须有**环检测**（脏数据可能出现 A→B→A）
- 递归深度上限（如 10 层），超过则记录告警并截断
- `DataScope` 结果缓存到 Redis，TTL 5 分钟；组织调整后主动失效
- 空部门、无下属、跨部门兼岗都要有测试用例

## 验收标准

- [ ] 越权用例：查非管辖部门返回空集
- [ ] 环检测用例：构造 A→B→A 不导致栈溢出
- [ ] 兼岗用例：多部门用户权限取并集（或按确认规则）
- [ ] 缓存失效：组织调整后 5 分钟内生效
- [ ] 权限判定耗时 P95 < 10ms（命中缓存）

## 风险

- **递归性能**：层级深时每次展开都查库，必须缓存
- **脏数据**：部门 ID 为空、父节点不存在、自我引用
- **口径不一致**：HR 系统的「部门」与业务系统可能不是同一套编码
- **越权风险最高**：这是整个系统最敏感的模块，改动必须走代码评审
