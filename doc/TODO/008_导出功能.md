| 字段 | 内容 |

## 背景

产品诉求里提到「生成结构化结果用于导出」，但当前明确不做。
`PermissionChecker` 中已预留 `EXPORT` 权限位，但**不实现**任何导出逻辑。

## 为什么暂缓

1. 导出是人数据外泄的最大口子，需要独立的审计与审批设计，不能顺手做。
2. 优先级低于核心问答链路。
3. 导出格式、范围、有效期、水印规则均未定义。

## 目标（未来）

异步导出，流程：

```
请求导出 → 权限校验（EXPORT 位）→ 生成任务 → 异步执行 → 生成文件 → 通知下载
                                                              ↓
                                                    有效期 24h，过期自动删除
```

## 关键设计约束

1. **权限**：必须同时具备「数据范围权限」与「导出功能权限」，缺一不可。
2. **审计**：记录谁、何时、导出了哪些字段、多少行、下载了几次。
3. **水印**：文件内嵌「导出人 + 时间 + traceId」，便于追溯泄漏源。
4. **脱敏级别可配**：默认脱敏；明文导出需要更高权限 + 二次确认。
5. **行数上限**：单次导出 ≤ 5000 行，超出需拆分或走审批。
6. **绩效数据**：沿用 `doc/TODO/006_绩效数据送模方案.md` 的规则，
   导出同样禁止员工级绩效明细。

## 验收标准（未来）

- [ ] 无 EXPORT 权限时请求被拒绝，且记录审计
- [ ] 导出文件含水印
- [ ] 超过 24h 的文件不可下载
- [ ] 导出内容中的 PII 与接口返回的脱敏级别一致
- [ ] 单次导出耗时 > 30s 时走异步，不阻塞请求线程

## 风险

- **数据外泄**：这是最高风险功能，必须有审计与审批
- **大文件**：内存溢出，需要流式写文件
- **并发**：同一用户重复点击导致重复生成，需要幂等键
- **清理**：过期文件未清理会占用存储并扩大泄漏面
